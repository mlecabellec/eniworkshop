# Constraint 0020

## Title

AI Agent Rules and Submission Protocols

*(Imported and consolidated from Nunki CS-0020 and Quasar CS-0030 / CS-0070.)*

## Description

This constraint governs AI-assisted development, impact analysis, and submission hygiene in **ENI Workshop**.

### 1. Traceability & Explanation
- **[CS-0020.1]** Every generated or modified code asset must cite its `REQ-*`, `FR-*`, `TSK-*`, `BUG-*`, or `FIX-*` identifier.
- **[CS-0020.2]** Explain generated code, design trade-offs, and requirement evaluations in clear technical prose.
- **[CS-0020.3]** Conduct impact and deletion analysis before removing or refactoring public interfaces or architectural modules.

### 2. Verification & Testing Mandates
- **[CS-0020.4]** All generated production code must be covered by JUnit 5 unit and integration tests, including null/boundary/invalid argument tests and concurrency tests for multithreaded components.
- **[CS-0020.5]** Before requesting submission clearance, the full local Maven build (`mvn verify`) and frontend check (`npm run check`) must pass cleanly.

### 3. Submission Clearance (from Quasar CS-0070)
- **[CS-0020.6]** Human validation is required before `git commit`, `git push`, deletion of architecturally significant code, or modification of constraint/requirement definitions.
- **[CS-0020.7]** No assumed approval: every VCS commit/push requires explicit user confirmation in the active session, preceded by build, test, and deletion-analysis evidence.

## Verification

- Verified via Maven build logs (`mvn verify`), test execution reports, and git diff/status audit prior to commits.
